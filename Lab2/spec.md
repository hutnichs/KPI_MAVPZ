1. Актори
Клієнт (Customer) — зареєстрований користувач, який керує профілем, домашніми тваринами, купує товари, здійснює оплату, залишає відгуки та снапшоти тварин.

Працівник магазину / Менеджер (Employee) — внутрішній користувач (адміністратор/менеджер), який додає товари, керує каталогом, обробляє замовлення та координує відправлення.

Зовнішній платіжний шлюз (Payment Gateway) (Зовнішня система) — сторонній сервіс обробки платежів, що повертає статус транзакції.

Служба доставки (Delivery Service API) (Зовнішня система) — зовнішня система логістики для генерації трекінг-номерів та оновлення статусу перевезення.

2. Головні цілі
G-1 Забезпечити зручний пошук та замовлення товарів для тварин із урахуванням їх специфічних потреб.

G-2 Гарантувати незмінність історичних даних (ціни закупівлі, стани тварин у відгуках, чеки про оплату) за допомогою архітектурних рішень (снапшоти, м'яке видалення).

G-3 Надати повний цикл управління каталогом, замовленнями та логістикою для персоналу.

3. EARS-вимоги

3.1 Профіль і тварини
ID	Вимога
REQ-001	WHEN Відвідувач надсилає форму реєстрації з name, surname, email, phone і zip_code, the system SHALL створити запис Customer з is_deleted = false.
REQ-002	IF email з форми реєстрації вже належить іншому Customer, THEN the system SHALL відхилити реєстрацію і повідомити, що email зайнятий.
REQ-003	WHEN Клієнт додає тварину з name і species, the system SHALL створити запис Pet, пов'язаний із цим Customer.
REQ-004	WHEN Клієнт видаляє тварину, the system SHALL встановити Pet.is_deleted = true і SHALL NOT видаляти запис фізично.
3.2 Каталог
ID	Вимога
REQ-005	WHEN Клієнт виконує пошук за title, category або tag, the system SHALL повернути лише товари з is_deleted = false.
REQ-006	WHILE Product.stock дорівнює 0, the system SHALL позначати товар як недоступний для замовлення.
3.3 Замовлення, оплата, доставка
ID	Вимога
REQ-007 WHEN Клієнт надсилає запит на оформлення замовлення з переліком товарів та їх кількістю, the system SHALL створити запис Orders зі status = "new" і по одному запису Order_Prod на кожну позицію, записавши price_at_purchase = поточна Product.price.
REQ-008 IF кількість обраного товару досягає Product.stock, THEN the system SHALL заблокувати можливість збільшити кількість цього товару та повідомити Клієнта про досягнення максимального доступного залишку.
REQ-009	WHEN замовлення створено, the system SHALL надіслати Платіжному шлюзу запит на оплату суми замовлення.
REQ-010	WHEN Платіжний шлюз повертає результат, the system SHALL створити запис Payment зі status, що відповідає результату, і amount.
REQ-011	IF Платіжний шлюз не відповів за встановлений час, THEN the system SHALL зберегти Payment зі status = "failed" і дозволити Клієнту повторну спробу оплати.
REQ-012	WHEN Працівник відправляє оплачене замовлення, the system SHALL створити Delivery, запросити tracking_num у Служби доставки і зберегти його.
REQ-013	WHEN Служба доставки повідомляє зміну статусу перевезення, the system SHALL оновити Delivery.status.
3.4 Відгуки
ID	Вимога
REQ-014	WHEN Клієнт надсилає відгук із rating від 1 до 5, the system SHALL створити запис Review для вказаного товару.
REQ-015 IF Клієнт обрав тварин під час створення відгуку, THEN the system SHALL для кожної обраної тварини створити запис Review_Pet_Snapshot із копією атрибутів Pet на момент надсилання.
REQ-016 WHEN Клієнт видаляє відгук, the system SHALL встановити Review.is_deleted = true, приховуючи відгук та його снапшоти з публічного перегляду без їх фізичного видалення з бази даних.
3.5 Персонал і каталог
ID	Вимога
REQ-017	WHEN Працівник створює товар, the system SHALL записати його empl_id в Product.added_by.
REQ-018	WHEN Працівник бере замовлення в обробку, the system SHALL записати його empl_id в Orders.processed_by.
REQ-019	WHEN Працівник відправляє замовлення, the system SHALL записати його empl_id в Delivery.shipped_by.
4. User stories
ID	Історія
US-01	Як Відвідувач, я хочу зареєструватися, щоб оформлювати замовлення.
US-02	Як Клієнт, я хочу додати своїх тварин, щоб підписувати ними відгуки.
US-03	Як Клієнт, я хочу шукати товари за категорією і тегами, щоб швидко знайти потрібне.
US-04 Як Клієнт, я хочу сформувати замовлення з обраних товарів й оплатити його онлайн.
US-05	Як Клієнт, я хочу повторити оплату після невдалої спроби, щоб не створювати замовлення заново.
US-06	Як Клієнт, я хочу залишити відгук із даними про мою тварину, щоб інші бачили, кому товар підійшов.
US-07	Як Працівник, я хочу додавати й редагувати товари, щоб підтримувати каталог актуальним.
US-08 Як Працівник, я хочу брати нові замовлення в обробку, щоб змінити їхній статус і розпочати підготовку.
US-09 Як Працівник, я хочу відправити оплачене замовлення, щоб згенерувати трекінг-номер через Службу доставки.
US-10	Як Служба доставки, я хочу передавати статуси перевезення, щоб клієнт бачив актуальний стан.
