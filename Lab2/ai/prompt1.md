Відповідь: 
1. Актори
Клієнт (Customer) — зареєстрований користувач, який керує профілем, домашніми тваринами, створює вішлісти, купує товари, здійснює оплату, залишає відгуки та снапшоти тварин.

Працівник магазину / Менеджер (Employee) — внутрішній користувач (адміністратор/менеджер), який додає товари, керує каталогом, обробляє замовлення та координує відправлення.

Зовнішній платіжний шлюз (Payment Gateway) (Зовнішня система) — сторонній сервіс обробки платежів, що повертає статус транзакції.

Служба доставки (Delivery Service API) (Зовнішня система) — зовнішня система логістики для генерації трекінг-номерів та оновлення статусу перевезення.

2. Головні цілі
G-1 Забезпечити зручний пошук та замовлення товарів для тварин із урахуванням їх специфічних потреб.

G-2 Гарантувати незмінність історичних даних (ціни закупівлі, стани тварин у відгуках, чеки про оплату) за допомогою архітектурних рішень (снапшоти, м'яке видалення).

G-3 Надати повний цикл управління каталогом, замовленнями та логістикою для персоналу.

3. EARS-вимоги

3.1 Профіль і тварини
ID	Вимога
REQ-001	WHEN відвідувач надсилає форму реєстрації з name, surname, email, phone і zip_code, the system SHALL створити запис Customer з is_deleted = false.
REQ-002	IF email з форми реєстрації вже належить іншому Customer, THEN the system SHALL відхилити реєстрацію і повідомити, що email зайнятий.
REQ-003	WHEN Клієнт додає тварину з name і species, the system SHALL створити запис Pet, пов'язаний із цим Customer.
REQ-004	WHEN Клієнт видаляє тварину, the system SHALL встановити Pet.is_deleted = true і SHALL NOT видаляти запис фізично.
3.2 Каталог і вішліст
ID	Вимога
REQ-005	WHEN Клієнт виконує пошук за title, category або tag, the system SHALL повернути лише товари з is_deleted = false.
REQ-006	WHEN Клієнт додає товар до вішлісту, the system SHALL зберегти зв'язок Customer–Product.
REQ-007	WHILE Product.stock дорівнює 0, the system SHALL позначати товар як недоступний для замовлення.
3.3 Замовлення, оплата, доставка
ID	Вимога
REQ-008	WHEN Клієнт підтверджує кошик, the system SHALL створити Orders зі status = "new" і по одному запису Order_Prod на кожну позицію, записавши price_at_purchase = поточна Product.price.
REQ-009	IF quantity позиції перевищує Product.stock, THEN the system SHALL відхилити оформлення замовлення і вказати товар, якого бракує.
REQ-010	WHEN замовлення створено, the system SHALL надіслати Платіжному шлюзу запит на оплату суми замовлення.
REQ-011	WHEN Платіжний шлюз повертає результат, the system SHALL створити запис Payment зі status, що відповідає результату, і amount.
REQ-012	IF Платіжний шлюз не відповів за встановлений час, THEN the system SHALL зберегти Payment зі status = "failed" і дозволити Клієнту повторну спробу оплати.
REQ-013	WHEN Працівник відправляє оплачене замовлення, the system SHALL створити Delivery, запросити tracking_num у Служби доставки і зберегти його.
REQ-014	WHEN Служба доставки повідомляє зміну статусу перевезення, the system SHALL оновити Delivery.status.
3.4 Відгуки
ID	Вимога
REQ-015	WHEN Клієнт надсилає відгук із rating від 1 до 5, the system SHALL створити запис Review для вказаного товару.
REQ-016	IF rating поза діапазоном 1–5, THEN the system SHALL відхилити відгук.
REQ-017	WHERE Клієнт обирає тварин у відгуку, the system SHALL для кожної створити Review_Pet_Snapshot з копією атрибутів Pet на момент надсилання.
REQ-018	WHEN Клієнт видаляє відгук, the system SHALL встановити Review.is_deleted = true і зберегти його снапшоти.
3.5 Персонал і каталог
ID	Вимога
REQ-019	WHEN Працівник створює товар, the system SHALL записати його empl_id в Product.added_by.
REQ-020	WHEN Працівник бере замовлення в обробку, the system SHALL записати його empl_id в Orders.processed_by.
4. User stories
ID	Історія
US-01	Як відвідувач, я хочу зареєструватися, щоб оформлювати замовлення.
US-02	Як Клієнт, я хочу додати своїх тварин, щоб підписувати ними відгуки.
US-03	Як Клієнт, я хочу шукати товари за категорією і тегами, щоб швидко знайти потрібне.
US-04	Як Клієнт, я хочу додавати товари у вішліст, щоб купити їх пізніше.
US-05	Як Клієнт, я хочу оформити замовлення й оплатити його онлайн.
US-06	Як Клієнт, я хочу повторити оплату після невдалої спроби, щоб не створювати замовлення заново.
US-07	Як Клієнт, я хочу залишити відгук із даними про мою тварину, щоб інші бачили, кому товар підійшов.
US-08	Як Працівник, я хочу додавати й редагувати товари, щоб підтримувати каталог актуальним.
US-09	Як Працівник, я хочу брати замовлення в обробку й відправляти їх, щоб клієнти отримували товар.
US-10	Як Служба доставки, я хочу передавати статуси перевезення, щоб клієнт бачив актуальний стан.
